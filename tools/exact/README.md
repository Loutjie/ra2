# Exact balance generator

The lobby option **Balance: Reimagined / Exact** (`LobbyPrerequisiteDropdown@BALANCE` in
`mods/ra2/rules/player.yaml`) grants every player `balance.reimagined` or `balance.exact`.
Exact gives each player-buildable RA2 object a twin `<name>.exact` with the original
`rules.ini` balance. Everything Exact is generated by this package from the base RA2
`rules.ini` (not `rulesmd.ini`) and the mod's resolved rules. Never edit the generated
files by hand: change the generator, the conversions or the exceptions, and regenerate.

## Regenerating

Needs a built mod (`make`), `dotnet` on `PATH`, and the original `rules.ini`:

```sh
cd tools
RA2INI=~/Projects/ra2-reference/ini python3 -m exact.generate          # rewrite the files
RA2INI=~/Projects/ra2-reference/ini python3 -m exact.generate --check  # exit 1 if any is out of date
```

`RA2INI` is the folder holding `ra2.mix__local.mix__rules.ini`; it defaults to
`~/Projects/ra2-reference/ini`. Game data is never copied into the repository.

The generator is deterministic: two runs give byte-identical files, and a run reads the
base actors with the previous run's additions stripped, so `--check` is clean straight
after a regeneration. Regenerate after any change to a base actor, weapon or `ai.yaml`
that a twin inherits from.

A new generated rules file must exist before the mod can load it: when adding one to
`mod.yaml`, first create it with only the header line, then run the generator.

## What is generated

Each file starts with `# GENERATED by tools/exact/generate.py from rules.ini — do not edit`.

| File | Contents | Module |
|---|---|---|
| `mods/ra2/rules/exact/actors.yaml` | twin actors `<name>.exact` (`Inherits` the base, overrides RA2 values, `~balance.exact`); the header lists untwinned buildables and RA2 values with no trait to go to | `actors.py`, `model.py` |
| `mods/ra2/rules/exact/reimagined.yaml` | the overlay on the base actors: `~balance.reimagined` and `ReplaceOnPrerequisite@BALANCE` into the twin; twin repair/rearm hosts appended for untwinned actors | `actors.py` |
| `mods/ra2/rules/exact/globals.yaml` | RA2's global and special rules on the twins (veterancy, economy, superweapons, Iron Curtain, death weapons, Spy Satellite) and the Exact/Reimagined trait pairs of the neutral tech buildings | `globals.py` |
| `mods/ra2/rules/exact/ai.yaml` | the AI bot modules' actor lists with each twin beside its base; support power decisions for Exact powers with another OrderName | `ai.py` |
| `mods/ra2/weapons/exact/weapons.yaml` | twin weapons `<weapon>.exact` with RA2 values | `weapons.py` |
| `tools/exact/weapon_exceptions.json` | weapons kept as `Inherits` stubs, RA2 weapons without a mod counterpart, projectile speed notes | `weapons.py` |
| `mods/ra2/rules/exact/EXCEPTIONS.md` | the exceptions report (below) | `exceptions.py` |

Tech buildings (`caairp`, `cahosp`, `caoild`, `caoutp`, `cathosp`) are not twinned: their
balance traits switch on the owner's `balance.exact` via `GrantConditionOnPrerequisite@BALANCE`.

Player-level production rules (RA2's factory and low-power rules) are not generated: they
live in `BalanceProductionQueue` (`OpenRA.Mods.RA2/Traits/Player/BalanceProductionQueue.cs`).

### The AI

The bot modules in `mods/ra2/rules/ai.yaml` name actors. `ai.py` checks every field of
every `*BotModule` / `*BotManager` trait and, where a name has a twin, adds the twin beside
it: comma lists are written out again in full (`McvTypes: amcv, amcv.exact, smcv,
smcv.exact`), dictionaries such as `BuildingFractions` and `UnitsToBuild` get only the
added `<name>.exact` keys. The AI only builds what its queues offer, so each mode uses the
names that are buildable in it. `McvTypes` must name the twin MCVs, or the AI will not deploy
its starting MCV in Exact. Support power decisions are keyed by `OrderName`; a decision is
copied only for a power whose Exact side uses another `OrderName` (none today: the tech
airport's `*ParatroopersExact` powers have no AI decision).

## Conversions and exceptions

Every RA2 number goes through `conversions.py`; the research behind its constants is in
`TIMING.md`. Where the mod models a mechanic differently, an entry of `exceptions.py` adjusts
the twins, and every such case is listed with its reason and the values it affected in
`mods/ra2/rules/exact/EXCEPTIONS.md`. Read that file to see where Exact is not a literal copy
of `rules.ini`.

### Pending: RA2's frame rate

`RA2_FRAMES_PER_SECOND` in `conversions.py` is not settled. Until an in-game measurement
(`TIMING.md`) decides it, it falls back to 25, one RA2 frame per OpenRA tick, which is what
the mod does today; the best-supported value is 30. `MINUTES_ARE_FRAMES` (currently `False`:
a `rules.ini` minute is a wall-clock minute, 1500 ticks) is the related open decision. Changing
either constant and regenerating rescales every time, speed and turn rate in Exact.

## Tests

Run from the repository root: `python3 -m pytest tools -q` (also part of `make unit-test`).

- **Reimagined snapshot** (`tests/test_reimagined_unchanged.py`, `reimagined-snapshot.json`):
  every buildable actor, the neutral tech buildings and every weapon they reference must
  resolve exactly as they did before balance modes. Allowed differences only: the
  `~balance.reimagined` prerequisite, `ReplaceOnPrerequisite@BALANCE`, twin names appended
  after their base in repair/rearm host lists, and the tech buildings' `@EXACT` traits and
  condition (a `X@REIMAGINED` trait must equal the original `X`). The snapshot is a fixed
  record; regenerate it (`python3 -m exact.snapshot --write`) only for an intended change
  to the Reimagined balance.
- **Unit tests** (`tests/test_*.py`) use inline fictional data.
- **Integration tests** (marked `integration`; need a built mod) read the committed files and
  the mod as the engine resolves it: `tests/test_integration.py` checks the twin count, that
  each faction reaches every Exact buildable from its MCV twin (and the same set as in
  Reimagined), sample RA2 values, that starting units are replaced by twins in Exact, and
  that the AI lists name the twins.
- **Up-to-date check**: `test_generated_files_up_to_date` regenerates in memory and compares
  with the committed files.

### Without game data (CI)

CI has no `rules.ini`. Tests that need it (they use the `ra2ini` fixture: the up-to-date
check and the checks against real `rules.ini` values) skip. The snapshot and integration
tests still run against the committed generated files, and
`test_generated_lists_match_resolved_mod` catches a base actor whose prerequisites or hosts
changed without a regeneration. Run `python3 -m exact.generate --check` locally before
pushing a change that a twin inherits from.

## Merging other branches

The separate airfield-capacity branch adds `PadLimitedProductionQueue`. When it is merged
with this work, `PadLimitedProductionQueue` must derive from `BalanceProductionQueue` (not
`ProductionQueue`), or aircraft queues lose RA2's production rules in Exact, and the
generator must be rerun so the twins inherit its pad-bound traits.
